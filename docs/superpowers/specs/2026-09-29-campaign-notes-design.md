# 캠페인별 메모 — Design Spec

**Date:** 2026-09-29
**Status:** Draft

---

## Problem

AO 탭에서 캠페인 데이터를 보다가 "이 캠페인은 격주 발송이라 하락이 정상" 같은 특이사항을 남길 곳이 없다. 지금 캠페인 관련 상태(모니터링 대상 체크 등)는 전부 `localStorage`에만 저장되는데, 메모는 같은 스프레드시트(=같은 고객사)를 보는 팀원 전체가 봐야 해서 브라우저 로컬 저장으로는 안 된다.

## Solution

캠페인별 자유 텍스트 메모 1개를, 지금 AO 탭이 읽어오는 바로 그 스프레드시트 안의 새 탭(`캠페인_메모`)에 저장하고, AO 탭 캠페인별 추이 섹션에 항상 보이는 텍스트 박스로 노출한다.

> **참고 (저장소 변경 이력)**: 최초 설계는 Vercel KV, 그다음 Upstash Redis(외부 벤더)를 검토했으나, "새로운 서드파티 벤더 계정을 늘리고 싶지 않고 이미 쓰는 Google 생태계 안에 머물고 싶다"는 이유로 최종적으로 Google Sheets(서비스 계정으로 쓰기) 기반으로 변경했다.

---

## 데이터 모델

지금 AO 대시보드가 읽어오는 스프레드시트(설정 탭에서 연결한 spreadsheetId, 또는 서버 기본 연결)에 `캠페인_메모`라는 탭을 **사람이 미리 만들어둔다** (앱이 자동으로 탭을 생성하지 않는다 — 자동 생성 로직 자체를 두지 않아 구조를 단순하게 유지).

- A열: `캠페인명` (헤더 `A1`)
- B열: `메모` (헤더 `B1`)
- 2행부터 캠페인당 한 행

캠페인 스코핑(어느 고객사 메모인지)은 "메모가 어느 스프레드시트 파일 안에 들어있는가"로 자연스럽게 결정된다 — 별도의 스프레드시트ID 컬럼이나 외부 키가 필요 없다. 지금은 11번가 하나만 신경 쓴다(2컬럼으로 충분) — 나중에 다른 고객사가 생기면 그 고객사도 자기 스프레드시트에 같은 이름의 탭을 만들면 자동으로 해결된다(컬럼 추가 불필요).

메모 개수는 캠페인당 최대 1개(같은 캠페인명 행을 찾아 덮어씀). 날짜별 로그, 작성자 기록, 수정 이력은 범위 밖.

## 백엔드

`api/sheets.ts`와 같은 패턴으로 `api/campaign-notes.ts`를 새로 추가한다 (Vercel 서버리스 함수, Google Sheets API를 plain `fetch()`로 직접 호출 + `google-auth-library`로 서비스 계정 인증만 처리 — 무거운 `googleapis` SDK는 쓰지 않음, 기존 `lib/googleSheets.ts`가 이미 SDK 없이 REST 호출 방식이라 그 스타일을 유지).

| Method | Path | Body/Query | 설명 |
|---|---|---|---|
| GET | `/api/campaign-notes` | `?spreadsheetId=X` | `캠페인_메모!A:B` 범위를 읽어서 `{ [campaign]: string }`로 반환 |
| PUT | `/api/campaign-notes` | `{ spreadsheetId, campaign, note }` | `캠페인_메모` 탭에서 campaign이 있는 행을 찾아 메모(B열)만 덮어쓰고, 없으면 새 행을 추가 |

**절대 규칙**: 모든 Sheets API 호출은 `캠페인_메모!A:B`라는 고정 문자열 range만 사용한다. 탭 이름을 요청 파라미터나 다른 값으로부터 동적으로 만들지 않는다 — 이 서비스 계정은 스프레드시트 파일 전체(`브레이즈 푸시 실적` 등 실제 실적 데이터 탭 포함)에 대한 편집 권한을 갖게 되므로, 코드가 실수로라도 다른 탭을 건드릴 경로 자체를 원천 차단한다. 스프레드시트 전체에 영향을 주는 호출(`batchUpdate`로 탭 추가/삭제 등)은 쓰지 않고, `values.get`/`values.update`/`values.append`만 사용한다.

인증/권한 체크(HTTP 요청 레벨)는 없음 — 기존 `api/sheets.ts`와 동일하게 "링크를 가진 사람은 누구나" 모델을 따른다. spreadsheetId는 클라이언트가 보내는 값을 그대로 신뢰한다(이미 시트 읽기에서도 같은 신뢰 모델).

읽기(GET)와 저장을 위한 행 탐색(PUT) 모두 `values.get`으로 `캠페인_메모!A:B` 전체를 읽는다 — Redis 해시와 달리 "캠페인명으로 그 칸만" 바로 조회하는 방법이 없어서, 매번 전체를 읽고 그 안에서 일치하는 행을 찾는다(지금 규모 — 캠페인 수백 개 이하 — 에서는 문제 없음). 찾은 행이 있으면 `values.update`로 그 행의 B열만, 없으면 `values.append`로 새 행을 추가한다.

**동시 저장 경쟁**: 두 사람이 거의 동시에 서로 다른 캠페인 메모를 저장하면, 한쪽의 "행 찾기" 결과가 그 사이 갱신된 시트 상태를 반영 못 해 드물게 경합이 생길 수 있다(Redis `HSET`처럼 필드 단위 원자적 쓰기가 아님). 이 앱의 실제 사용 빈도(팀 몇 명이 가끔 메모 남기는 정도)에서는 무시 가능한 리스크로 판단하고 범위 밖으로 둔다.

### 사전 설정 (배포자가 직접 해야 함)

1. `캠페인_메모` 탭을 대상 스프레드시트에 직접 만든다 (`A1`=`캠페인명`, `B1`=`메모`) — **이미 완료됨**
2. Google Cloud Console에서 서비스 계정을 생성하고 JSON 키를 발급받는다
3. 그 스프레드시트를 서비스 계정 이메일 앞으로 **편집자**로 공유한다
4. 서비스 계정의 `client_email`, `private_key` 값을 서버 환경변수(`GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY`)로 등록한다 (로컬 개발 시 `.env`에도 동일하게)

이건 계정 생성/시트 공유가 필요한 수동 작업이라 코드로 대신할 수 없다. 값이 없으면 아래 에러 처리대로 조용히 비활성화된다.

## 프론트엔드

### 새 훅 `useCampaignNotesState(spreadsheetId: string)`

`hooks/useCampaignNotesState.ts`, `useSheetData`와 같은 자리. **변경 없음** — 백엔드 저장소가 바뀌어도 HTTP 계약(GET/PUT 모양)이 그대로라서 프론트 코드는 이미 구현된 그대로 재사용한다.

- `spreadsheetId`가 바뀔 때(설정 탭에서 연결 변경 시) `GET /api/campaign-notes`로 전체 메모를 로드해 `{ [campaign]: string }` 상태로 보관
- `saveNote(campaign, note)`:
  1. 로컬 상태를 먼저 업데이트 (입력 내용 즉시 반영)
  2. 백그라운드로 `PUT` 전송
  3. 실패 시 저장 실패 상태만 표시, 입력했던 텍스트는 유지 (타이핑한 내용이 날아가지 않게)

### UI

`CRMAlwaysOn.tsx`의 "캠페인별 추이" 섹션 헤더(현재 캠페인명이 표시되는 자리) 바로 아래 텍스트 박스. **변경 없음.**

- 로컬 `noteDraft` state를 두고 `notes[selectedCampaign]`이 로드되거나 `selectedCampaign`이 바뀔 때마다 그 값으로 동기화(리셋)한다 — 타이핑 중에도 텍스트박스가 즉시 반응하는 controlled input으로 동작하게 하기 위함
- `onChange`는 `noteDraft`만 갱신하고, `onBlur`에서 `saveNote(selectedCampaign, noteDraft)` 호출 (저장 실패 시에는 텍스트가 안 바뀌어도 재시도되도록 함) — 타이핑마다 저장하지 않고 포커스 이탈 시에만 (불필요한 쓰기 요청 최소화)
- placeholder: "이 캠페인 특이사항 메모..."
- 박스 옆에 저장 상태를 작은 텍스트로 표시: 저장 중 없음(즉시 로컬 반영이라 딜레이 체감 안 됨) / 저장됨(회색) / 저장 실패, 다시 시도(빨간색)

## 에러 처리

- **메모 로드 실패** (서비스 계정 미설정, 시트 접근 실패, 네트워크 오류 등): AO 탭 전체를 막지 않는다. 메모 영역만 빈 텍스트박스로 두고 조용히 넘어간다 — 메모는 부가 기능이라 탭 전체를 깨뜨리면 안 된다는 원칙 (`sheetData`의 필수 에러 처리와 다름).
- **저장 실패**: 인라인으로 "저장 실패, 다시 시도" 표시. 콘솔에 원인 로그.
- **서비스 계정 미설정 환경** (로컬 개발 등에서 환경변수 없음): GET은 빈 객체 반환, PUT은 명확한 에러 반환 → 프론트는 위 "저장 실패" 상태로 자연스럽게 처리됨. 별도 분기 불필요.
- **`캠페인_메모` 탭이 없거나 이름이 다를 때**: Sheets API가 범위 오류를 반환 → GET/PUT 모두 위와 동일하게 처리(빈 객체 / 에러). 탭을 자동으로 찾아주거나 만들어주지 않는다(사전 설정 1번 항목 참고).

## 테스트

이 프로젝트는 자동화 테스트가 없다(`package.json`에 `test` 스크립트 없음, `lint`/`type-check`만 있음). 기존 관례를 따라 자동 테스트는 추가하지 않고, `type-check` + 브라우저 수동 확인으로 검증한다.

수동 확인 체크리스트:
1. 캠페인 A 메모 작성 → 포커스 아웃 → "저장됨" 표시 → 새로고침해도 유지
2. 다른 캠페인으로 전환 → 메모 박스가 그 캠페인 메모로 바뀜(또는 빈 상태)
3. 서비스 계정 환경변수 없이 로컬 실행 → 메모 저장 시도 → "저장 실패" 표시되고 AO 탭 나머지 기능은 정상 동작
4. 설정 탭에서 스프레드시트 연결 바꾸기 → 메모 목록이 새 스프레드시트 것으로 다시 로드됨
5. 메모 저장 후 스프레드시트를 직접 열어서 `캠페인_메모` 탭에만 행이 추가/수정되고, 다른 탭(`브레이즈 푸시 실적` 등)은 전혀 안 바뀌었는지 확인

## Out of Scope

- 메모 작성자/수정 시각 기록
- 메모 수정 이력(로그)
- 메모 검색/전체 목록 보기
- 여러 고객사가 하나의 스프레드시트를 공유해서 쓰는 상황(스프레드시트ID 컬럼으로 구분) — 지금은 고객사별로 각자의 스프레드시트를 쓰는 구조라 범위 밖. 필요해지면 그때 컬럼 추가
- `캠페인_메모` 탭 자동 생성
